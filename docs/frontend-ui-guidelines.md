# 前端 UI / UX 统一规范

## 目标

让功能页共享一致的信息层级、操作入口、表单、数据区域和响应式行为，同时保留各业务模块自身需要的工作流程。统一的是视觉语言和交互规则，不是把所有页面做成同一种布局。

## 设计令牌与样式职责

- `web/src/styles/tokens.css`：颜色、语义状态、间距、字体、圆角、阴影、层级和动效令牌的唯一来源。
- `web/src/styles/ui-kit.css`：项目自有通用组件与页面组合基类；新页面优先复用这里的类。
- `web/src/styles/tdesign-theme.css`：把项目语义令牌映射到 TDesign 变量。
- `web/src/styles/tdesign-skin.css` 与 `tdesign-overrides.css`：只处理 TDesign 组件皮肤和必要的组件行为覆盖，不在页面内重复定义组件库外观。
- `web/src/styles/modal-system.css`：项目 Modal（vue-final-modal）的尺寸、桌面居中和移动端抽屉定位。
- `theme-stripe.css`、`theme-dark.css`、`ui-refined.css`、`ui-polish.css`：目前仍承载兼容样式。迁移期间不直接删除；每次确认调用点和视觉结果后再逐步收敛。

## 页面结构基类

新页面或正在改造的页面按需组合，不要求每个页面机械地使用全部类：

- `.ui-page-shell`：页面纵向节奏与最小宽度。
- `.ui-page-header`、`.ui-page-heading`、`.ui-page-title`、`.ui-page-description`：页面标题、用途说明。
- `.ui-page-actions`：页面级主次操作。
- `.ui-page-section`、`.ui-section-heading`、`.ui-section-title`：内容分区。
- `.ui-toolbar`、`.ui-filter-bar`：筛选与批量操作区。
- `.ui-data-surface`、`.ui-table-wrap`：数据容器与窄屏横向滚动边界。
- `.ui-form-grid`、`.ui-form-field`、`.ui-form-label`、`.ui-form-help`：表单层级与响应式栅格。
- `.ui-empty-panel`：轻量空数据承载区；复杂空状态继续使用 `EmptyState.vue`。

## 页面类型与信息架构

1. **管理列表型**：标题/说明 → 主操作 → 搜索筛选 → 批量操作 → 表格/列表 → 分页。
2. **任务操作型**：标题/任务状态 → 关键配置 → 目标选择 → 执行主操作 → 进度与结果。
3. **监控日志型**：标题/运行状态 → 时间与级别筛选 → 指标摘要（确有价值时）→ 日志/事件流。
4. **数据总览型**：标题/范围 → 核心指标 → 趋势/分布 → 风险与最近活动。
5. **设置配置型**：标题/说明 → 分组表单 → 保存操作；危险操作独立分区并明确后果。

## 交互与视觉验收

- 每个页面首屏能看出当前模块用途和最重要的下一步操作。
- 主操作只有一个明确视觉主位；取消、刷新、导出、删除等按次级/危险级区分。
- 同一页面不混用多套按钮高度、圆角、边框和状态色。
- 表单标签、必填提示、帮助文案、错误反馈和保存状态完整。
- 列表具备加载、空、错误、无筛选结果状态；长表格在窄屏有明确滚动边界。
- 桌面弹窗居中且尺寸受控；移动端弹窗采用既定抽屉规则，内容区独立滚动。
- 触屏主要操作目标至少 44px；键盘焦点可见；尊重减少动态效果偏好。
- 颜色、间距、字号、圆角、阴影优先使用语义令牌，不在新页面增加硬编码值。
- 改造只调整呈现层，不改变 API、权限、业务状态和危险操作语义。

## 迁移策略

1. 先建立共享页面组合基类（本次已加入 `ui-kit.css`），不批量替换现有页面。
2. 选择一个高频、结构典型的管理列表页试点，验证桌面、窄屏、深浅主题与状态分支。
3. 将验证通过的模式迁移到群发/任务等操作页，再迁移监控与设置。
4. 每批检查差异、运行前端构建/类型检查/单测及相关 E2E；无真实浏览器截图时明确标记为未完成视觉验收。
5. 旧样式文件只有在调用点迁移完成、视觉回归通过后才删除。
